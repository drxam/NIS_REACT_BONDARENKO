Суть приложения
Мини канбан-доска в браузере. Есть три статуса задач: To Do, In Progress, Done. Задачи можно создавать, просматривать справа в панели деталей, перемещать между статусами мышкой (drag and drop) или через меню действий, а ненужные задачи трешить.

React
React отвечает за разбиение интерфейса на небольшие переиспользуемые компоненты: доска, колонка, карточка задачи, панель деталей. Он удобен тем, что обновляет только изменившиеся части экрана, не нужно вручную работать с DOM. Аналоги — Vue, Angular.

TypeScript
TypeScript даёт типизацию поверх JavaScript. В этом проекте типы описывают задачу, идентификаторы колонок, состояние стора. Это помогает отлавливать ошибки ещё во время разработки и облегчает рефакторинг. Аналоги по идее — Flow или просто строгие линтеры для JS.

Zustand
Zustand — основная «новая» технология в этом проекте. Это маленькая библиотека для хранения состояния, которая по ощущениям ближе к простому хуку, чем к тяжёлому фреймворку.

В сторе я завёл единое состояние для канбана: типы колонок, тип задачи, массив задач и функции, которые с этим всем работают. Самое главное тут — компактные экшены:

`src/store/kanbanStore.ts`
```ts
export const useKanbanStore = create<KanbanState>((set) => ({
  tasks: initialTasks,
  addTask: (columnId, title, description) =>
    set((state) => ({
      tasks: state.tasks.concat({
        id: Date.now().toString(),
        title,
        description,
        columnId,
      }),
    })),
  moveTask: (taskId, toColumnId) =>
    set((state) => ({
      tasks: state.tasks.map((task) =>
        task.id === taskId ? { ...task, columnId: toColumnId } : task
      ),
    })),
  deleteTask: (taskId) =>
    set((state) => ({
      tasks: state.tasks.filter((task) => task.id !== taskId),
    })),
}));
```

Компоненты подписываются только на нужные им части состояния. Например, доска берёт список задач и экшены так:

`src/components/KanbanBoard.tsx`
```ts
const tasks = useKanbanStore((state) => state.tasks);
const addTask = useKanbanStore((state) => state.addTask);
const moveTask = useKanbanStore((state) => state.moveTask);
const deleteTask = useKanbanStore((state) => state.deleteTask);
```

А дальше просто фильтрует задачи по колонкам и передаёт функции вниз в колонки и карточки.

Если сравнивать с Redux, то здесь нет редьюсеров, типов экшенов, отдельных файлов с константами. Всё состояние описано в одном месте через обычный объект и функции. По сравнению с Context API Zustand меньше заставляет думать о дереве компонентов: не нужно оборачивать всё в Provider и бояться лишних перерендеров, каждый компонент сам выбирает, что ему читать из стора. Для такого небольшого канбана это даёт простой и понятный код без «магии», но при этом состояние централизовано.

CSS
Стили написаны на чистом CSS в файле App.css. Я использовал современную тёмную тему, сетку для колонок и аккуратные тени. Аналоги — CSS‑фреймворки вроде Tailwind или Bootstrap.

Заключение
В процессе получилось собрать небольшой, но законченый инструмент: задачи можно создавать, двигать между статусами, удалять и подробно смотреть их карточку. React и TypeScript в связке ощущаются комфортно: типы немного замедляют на старте, но потом экономят время на отладке. Zustand приятно удивил простотой — для маленького проекта это почти идеальный вариант хранилища. В целом такой стек хорошо подходит для учебных и прототипных интерфейсов, и после этой работы стало понятнее, как строятся более сложные канбан‑подобные приложения.
